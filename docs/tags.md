# `docx_tags`

Модуль: `docx_blocks/tags.py`

Утилиты для поиска верхнеуровневых тегов с учётом вложенности.
Нужны, потому что регулярки вроде `\{block\b.*?\{/block\}` не
различают вложенные блоки:

    {block}
      {block}вложенный{/block}     <-- регулярка закроется здесь
    {/block}

## Публичный API

### `find_top_level(text, open_re, close_tag) -> list[tuple[int, int]]`

Возвращает список `(start, end)` для верхнеуровневых вхождений
открывающего тега и соответствующего закрывающего.

**Параметры**

- `text` — строка;
- `open_re` — regex открывающего тега (без группы);
- `close_tag` — строка закрывающего тега.

**Пример**

```python
from docx_blocks.tags import find_top_level

ranges = find_top_level(
    '{block}a{block}b{/block}c{/block}',
    r'\{block\b',
    '{/block}',
)
# [(0, 32)] — один блок верхнего уровня
```

### `find_blocks(text) -> list[str]`

Верхнеуровневые `{block ...}...{/block}`.

### `find_rows(text) -> list[str]`

Верхнеуровневые `{row ...}...{/row}`.

### `find_cells(text) -> list[str]`

Верхнеуровневые `{cell ...}...{/cell}`.

## Как это работает

Алгоритм простой: проходим по всем вхождениям
`open_re | close_tag`, считаем глубину. Каждый раз, когда
глубина возвращается к нулю, фиксируем пару.

## Использование

Внутри проекта:

```python
from docx_blocks.tags import find_blocks

blocks = find_blocks(text)   # список строк, каждая — целый блок
```

Это правильный способ разбить текст на блоки — иначе вложенные
блоки (например, внутри ячеек таблиц) будут закрываться не там,
где нужно.
